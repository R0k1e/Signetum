## Context

The owner approved completing the first four consumer-operation and validation
optimization stages. Daily commands must not trigger repeated complete suites.
Current state is derived; important reasoning is retained without transcripts.

## Decision

Make changed a source/selection explanation only and expose workflow status
through one read-only utility, replacing the observation-only status-all entry.
This replaces only the earlier changed-executes requirement; optional selection,
full default readiness and historical-source boundaries remain effective.
Keep the eight lifecycle operation boundaries. Retain one execution, journal
and evidence owner, and use consistent structured failures at public utilities.

Teach distinct-risk test placement and minimal sufficient decision rationale.
Report actual cost without timing budgets or changing failure verdicts.

Provide optional Python dependency selection through the existing provider,
duration-weighted scheduling through framework adapters, and source-bound CI
partition planning/execution/aggregation through supervised commands. Keep
repository paths and family mappings in consumer configuration. Unknown reach
falls back conservatively. Weight hints never remove tests. Partition evidence
must cover the exact declared universe once; it does not grant lifecycle ready,
final or delivery permission. Complete lifecycle final remains mandatory.

## Enforcement

Core behavior matrices, representative generated CLI execution and installed
artifact acceptance cover these boundaries. Remove replaced callers rather
than keeping permanent aliases. This change stops at clean ready and excludes
Perdura edits, RAM volumes, background deletion, integration and publication.
