## Context

The owner approved the six-part repair proposal and instructed implementation.
File-level supersession does not describe partial decision changes or current
system intent. Separate repeated records and retry-based green outcomes increase
maintenance and review burden. The product should remain a local standard skill
and command collection rather than become a service platform.

## Decision

A significant development event retains the approved source, rationale and
exact affected decision clauses. Stable clause IDs, versions and expected prior
values support targeted amendments, withdrawals, splits and merges. A current,
topic-organized working set is a verified projection of accepted history,
including context and relationships; there is one mutation owner for both.

Consolidate intent, approved behavior and necessary planning in one change
record. Preserve approval boundaries and original accepted history. Migrate
historical records through reviewed explicit mappings; do not guess granularity.
Capture source-relevant events before validation freezes the source; validation
success remains evidence outside the source and never causes a self-edit.

A diagnostic retry cannot clear the first failure. Preserve both attempts and
require a fresh normal successful run after a fix. Command settlement observes
owned processes on every exit path and refuses a successful job that leaked.
The generic protocol does not impose an application language or runner.

Update actual Agent instructions alongside record formats. Market the product
as a reliable agentic development and delivery protocol, with reproducible
mechanism demonstrations and no invented impact measurements. Distribution is
one skill plus local commands; cross-machine systems and publication are out of
scope. Existing public identities are retained unless separately approved.

## Supersession boundary

Only the earlier alignment decision's acceptance of a recovered retry as a
potentially successful gate is replaced. Retry remains useful diagnostic
execution, but repeated-recovery thresholds cannot authorize a passed gate.
Exact source identities, remote-first delivery, approval boundaries, profiles,
workspace ownership, numbering and single-source generation remain in force.

## Alternatives

Whole-file override loses unaffected rules. Independently handwritten current
summaries drift from history. Logging every command creates unnecessary source
maintenance. A service platform expands the approved product. Retain granular
history and one generated current projection with local deterministic tools.

## Enforcement

The linked protocol specification owns all thirteen acceptance clauses.
Public command, real Git, process-ownership and installed-artifact scenarios
verify observable results. The implementation and generated runtime have one
maintained source. The owner instruction in this conversation confirms this
standalone decision before implementation.
