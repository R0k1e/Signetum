# Consumer adoption has one reviewed path

Status: Accepted
Review date: 2026-10-29
Supersedes: None
Superseded by: None

## Context

The owner approved reducing installation, review and daily-operation friction.
The three development principles govern maintainers; consumers need outcomes
and usable commands. Perdura must become a real consumer as well as a source
of experience, through the same path as other repositories.

## Decision

Keep internal taxonomy in maintainer policy. Give consumers one first-use guide
and an explicit local inspect, preview and apply path that preserves their
application runner and shows exact source-bound file changes. Installation is
not adoption or approval. Never overwrite a stale or changed target silently.

Bind semantic journal operations through the existing writer rather than
requiring handwritten transactions. Preserve its approval, concurrency,
idempotence and immutable-history guarantees. Surface retained historical
decision authorities alongside current clauses without pretending that source
discovery is an accepted semantic migration.

Generalize demonstrated stability lessons as conditional instructions. Prepare
Perdura to consume the generic tools; its policies and selector stay downstream.
Downstream replacement and retirement require actual adoption evidence and
separate authorization. Do not introduce a second runner or an upgrade service.

## Enforcement

Public CLI and installed-artifact acceptance exercise file preservation, stale
refusals, literal arguments and actual application commands. New implementation
uses shared owners and generated portable sources. Current source discovery
retains unmigrated authority explicitly. This change stops at member readiness.
