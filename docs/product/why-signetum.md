# Is Signetum useful for your repository?

Use Signetum when coding agents lose requirements between sessions, repeat old
decisions, or report success without identifying the source they checked.
It keeps an approved change, significant findings, current decisions and exact
validation evidence connected through local repository tools.

You review the intended behavior and consequential choices. The agent authors
records and gathers evidence. One current view helps the next agent discover
standing decisions and their original basis; one generated delivery review
makes the result inspectable without reading the whole conversation.

It is useful for one agent and for named members working in isolated worktrees.
It does not replace application tests or prove that natural language was fully
understood. Reduced review time and defect rates need real usage measurements;
they are not guarantees supplied by a passing check.

Start with the [first-use guide](../../QUICKSTART.md). The
[failure demonstrations](failure-demonstrations.md) show concrete refusal
behavior; [working with a change](protocol-in-practice.md) explains the review
boundary. Compare it with [specification tools](signetum-and-specification-tools.md)
if your repository already has a requirements workflow.
