# Implementation and distribution

`skills/signetum` is the standard public Skill. The installed setup engine owns
inspection, preview and exact approved adoption. Daily commands use the consuming
repository's portable runtime under `.agents/signetum`; application policy,
runners and delivery targets remain repository-owned. Updates are explicit.

## One maintained implementation

Portable modules are generated from enumerated engine owners, including source
and output hashes. They use the standard library and exact licensed bundled
PyYAML bytes; they do not import the installed engine or Pydantic. Refresh owned
upstream YAML resources only with the locked vendor utility and verify their
license and bytes.

`tests/fixtures/portable-python/` holds small internal acceptance inputs. Its generated runtime is
ignored output, not a second committed implementation. Rendering builds the full
runtime from installed source; tests prepare and reuse one immutable generated
fixture before parallel workers start. The declared preparation graph also
materializes that ignored fixture before type checks; a warm local cache is
never a prerequisite. Rendering copies inventoried files, not cache-only
directories. Existing generated bytes, when supplied,
must match their owner; tampering, unexpected files and symlink escapes refuse.
`runtime_generation --check` checks a materialized output without writing it.

The wheel bundles the same standard Skill and installable schemas. Source,
portable and installed tests each protect their actual boundary; pure matrices
belong once in core tests. Release/package identity follows the single main source,
with one package/Skill product version and independent schema revisions.

## Records and authority

One approved change owns outcomes, acceptance, exclusions and autonomy. Execution
steps cannot narrow that contract. Significant source history lives in
`changes/<id>/events.jsonl`, written only by its locked owner. Expected approval
and history digests, immutable source proofs, protected committed prefixes and
atomic replacement prevent stale or partial reinterpretation. Exact retries are
idempotent; refused requests append nothing.

Current clause decisions are derived. Accepted standalone cross-change authorities
retain their original basis. Historical ledgers/documents are read-only evidence,
not fallback approval or another authoring path. Retractions and exact approved
evidence retirements preserve earlier statements and provenance. Never hand-edit
JSON Lines, invent historical acceptance or maintain another decision summary.

## Adoption and customization

Inspection and preview execute no application command. Apply requires the exact
reviewed plan and unchanged source/targets, preserves unrelated files and rolls
back ordinary write failure. An interrupted write requires inspection and a fresh
preview. The local launcher dispatches to the adopted runtime; it downloads and
updates nothing during ordinary work.

Profiles declare versioned capabilities and dependencies, reject conflicts and
bind resolved identities into evidence. Repository tools/shards/gates explicitly
select execution. Existing-runner adapters preserve argv, deadlines and native
metadata; they do not infer languages or install application tools. Host Python
is separate from an application's language. See [the guide](../guide.md) and
[runner bindings](../guides/existing-runners.md).

Keep affected architecture and instructions current in the implementing change.
Reasons belong once in its significant history. Current pages describe actual
owners; they are not an exhaustive algorithm catalogue or execution diary.

## Source and disposable material

`src/signetum` owns the setup engine and portable source modules. Its subpackages
separate change accounting, validation, profiles and release boundaries; moving
modules solely to shrink a directory would add import churn without removing an
owner. `tests/fixture_rendering.py` validates the internal fixture and is not packaged
in the wheel. Adoption emits reviewed bindings into the existing project directly.

Keep production HTML/CSS/JS, the SVG mark, social image, font and its license in
source. Design-tool skills, context, concept variants, screenshots and review
output are local development material, not shipped product authorities. Keep
them outside the tracked tree. Build exports, generated runtime copies, virtual
environments and test reports are disposable output. Significant design choices
still belong in the existing change history, rather than a second design diary.

The internal `tests/fixtures/portable-python/uv.lock` pins the Python acceptance fixture's own dev
tools. Independent tests run `uv sync --locked` there without the installed engine.
It is neither a Skill installation requirement nor a file copied by adoption.
Removing it requires replacing that isolated environment evidence first. The
primary `uv.lock` separately pins development of Signetum itself.

The selection interface is language-neutral. Projects own algorithms and family
rules; no Python dependency selector is bundled. Self-use runs the complete
member gate. Core verifies request/source/target identity and preserves full
final validation, rather than claiming to prove a provider's dependency model.
The standard Skill owns common instructions. Adoption emits local command
bindings and a Skill pointer. Journal CLI parsing lives in `protocol_cli`;
`development_store` owns locked storage and authority checks, `development_log`
owns projection and `workflow_status` owns the derived workspace view.
