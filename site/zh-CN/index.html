让每次变更都有证据。

可靠的 agentic 开发与交付协议。一个标准 Skill 加本地命令，连接已批准的变更、当前决策、行为证据和显式交付。

它解决什么

用少量、明确的仓库权威，让 Agent 工作从第一条诉求到最终验收都可审查。

一份变更记录集中维护已记录的需求、验收、审批和执行步骤，由工具生成审阅视图。
理解现有实现架构入口和策略路由要求 Agent 先查清已有权威再修改。
当前决策从已接受的历史派生工作集，需要时再读取原始决策依据。
Agent Team 并行计划拥有独立 worktree，batch 只组装明确点名的成员。
交付可解释验证收据绑定精确提交，清楚说明每次交付包含什么。
质量面向行为单元与集成测试保护可观察契约，而不是锁死内部实现。

一条闭合链路

人的确认保留在关键边界，其余步骤明确、可重复，并由仓库自身定义。

  1. 成员工作区
  2. 已批准的变更
  3. 实现
  4. Ready
  5. 点名组装批次
  6. 最终验证
  7. 显式交付
  8. 人工验收

边界清楚

不只是 CI

CI 检查一个提交；Signetum 还负责需求闭环、并行开发治理和精确交付证据。

补全规格工具

规格工具描述期望行为；Signetum 把它连接到计划、工作区、验证与交付。

不是 Agent Runtime

你可以使用任何编码 Agent。Signetum 是随仓库长期存在的开发契约。

从现有仓库开始

保留应用已有的测试方式。Python、Node 和 Rust 可选绑定使用仓库自己的命令。安装 Skill 不会自动采用协议，也不授权交付。新仓库仍可从模板开始。

证据的边界

失败演示在临时仓库中验证需求归属遗漏、过期验证证据和发布中断。它们证明协议边界，不承诺软件没有缺陷，也不声称已测得审阅时间下降。历史决策在显式迁移前继续有效。
