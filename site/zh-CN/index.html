Signetum 是可靠的 agentic 开发与交付协议。通过一个标准 Skill，让决策、验证与交付始终对应同一次变更。

查看 Skill

粘贴给编码 Agent，先审阅接入方案再应用。

阅读安装提示
请从 https://github.com/R0k1e/Signetum/tree/main/skills/signetum 安装 Signetum Skill，选择一个明确审阅过的提交。用它检查当前项目并提出接入方案，保留现有工具，在应用前展示改动。

保留决策依据，
少写重复文档。

让下一位 Agent 和审阅者得到真正有用的上下文。重要内容只记一次，留在变更旁边。

记录选择，不抄写对话。
用一份 change.toml 和重要追加日志保留关键选择，从历史派生当前决策集合。
测试要能说明风险。
沿用已有测试方式。可选的选择机制缩小日常反馈范围，最终验证仍保持完整。
并行开发，显式汇合。
独立 worktree 隔离成员改动，点名的 batch 让合并后的源码在交付前可检查。

接入你已有的仓库，
保留熟悉的工具。

新项目或现有代码，都走同一个 Skill 接入流程。审阅配置后，日常开发在本地运行。

阅读接入指南
安装之后，仓库会改变什么？

Skill 提供 Agent 指令。经明确审阅的接入方案才会添加仓库本地命令和绑定，保留应用的元数据与已有工具。

还可以使用原来的测试工具吗？

可以，应用测试方式仍由仓库自己定义。协议需要宿主 Python；当前工作区操作还需要 Git、Mise 和 Worktrunk。接入指南列出了这些前置条件。

这些证据能证明什么？

它记录当前源码实际通过了哪些检查，以及哪些交付得到了批准。它不承诺软件没有缺陷，也不替代人的判断。

让下一次变更，留下清楚的依据。
