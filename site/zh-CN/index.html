可靠交付。

保留关键决策，协调独立开发，验证集成后的结果，交付检查过的同一份源码。适用于持续演进的项目，从单个 Agent 的长期开发到多 Agent 并行协作。

了解交付流程

粘贴给编码 Agent，先审阅接入方案再应用。

阅读安装提示
请从 https://github.com/R0k1e/Signetum/tree/main/skills/signetum 安装 Signetum Skill，选择一个明确审阅过的提交。用它检查当前项目并提出接入方案，保留现有工具，在应用前展示改动。

接续开发，
依然可靠。

上下文会更换，改动会交汇，交付会中断。让重要约定和验证结果有明确的归属。

决策能够接续。
重要依据只保留一次，从历史派生当前有效决定。后续 Agent 可以继续开发，避免重复讨论已经确认的取舍。
并行能够汇合。
隔离改动，约定共享接口，明确集成负责人。交付之前，验证合并后的整体结果。
验证保留失败事实。
沿用已有工具，按行为边界编写测试。可选的项目选择器缩短反馈，重试不清除首次失败，最终验证保持完整。
交付对应验证。
审阅与交付绑定检查过的源码。中断后先核对本地和远端状态，再继续同一次交付。

接入你已有的仓库，
保留熟悉的工具。

安装 Skill，让 Agent 检查仓库并提出本地绑定方案。确认配置后，沿用现有工具开始开发。

阅读接入指南
安装之后，仓库会改变什么？

Skill 提供 Agent 指令。经明确审阅的接入方案才会添加仓库本地命令和绑定，保留应用的元数据与已有工具。

还可以使用原来的测试工具吗？

可以，应用测试方式仍由仓库自己定义。协议需要宿主 Python；当前工作区操作还需要 Git、Mise 和 Worktrunk。接入指南列出了这些前置条件。

谁来组织多个 Agent？

由你和编码 Agent 宿主分配任务、组织 Agent。Signetum 提供共同指令、隔离工作区，以及明确的集成与交付边界；它不是全局 Agent 或机器资源调度器。
