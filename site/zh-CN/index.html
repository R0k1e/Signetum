仓库拥有的 Agent 开发流程

让每次变更都有证据。

Signetum 把需求、决策、实现、验证和交付连成一套可检查的仓库闭环，让质量不再依赖聊天记录，也不依赖某个 Agent 是否记得全部上下文。

查看 GitHub使用模板

它解决什么

用少量、明确的仓库权威，让 Agent 工作从第一条诉求到最终验收都可审查。

不漏需求Review 将每条诉求映射到已批准的 Specification，并显式暴露延期项。
理解现有实现架构入口和策略路由要求 Agent 先查清已有权威再修改。
降低验证 I/O按变更路径诊断，只在最终交付树执行一次完整门禁。
Agent Team 并行计划拥有独立 worktree，batch 只组装明确点名的成员。
交付可解释验证收据绑定精确提交，清楚说明每次交付包含什么。
质量面向行为单元与集成测试保护可观察契约，而不是锁死内部实现。

一条闭合链路

人的确认保留在关键边界，其余步骤明确、可重复，并由仓库自身定义。

  1. Review
  2. Specification
  3. Plan
  4. Worktree
  5. Batch
  6. Final
  7. Delivery
  8. Acceptance

边界清楚

不只是 CI

CI 检查一个提交；Signetum 还负责需求闭环、并行开发治理和精确交付证据。

补全规格工具

规格工具描述期望行为；Signetum 把它连接到计划、工作区、验证与交付。

不是 Agent Runtime

你可以使用任何编码 Agent。Signetum 是随仓库长期存在的开发契约。

克隆即可开发

核心保持语言中立且可组合，Python 是已验证的默认配置，uv、Ruff、ty、pytest 与行为门禁均已接通。由模板创建的仓库之后独立演进。
