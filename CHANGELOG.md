# Changelog

This file records user-visible Signetum releases. Earlier RepoSeal entries retain
their original release history. Git and accepted change records retain reasoning.

## 0.3.0 - Unreleased

- Center public entrypoints on reliable Agent delivery, including session handoffs,
  integrated validation and exact-source publication; refresh the generated signet.

- Focus the Skill on human decisions, parallel worktrees and reliable integration/delivery.
- Retain project selection interfaces; remove bundled Python reach and its optional command.
- Move private acceptance scaffolding to tests, remove future ADR numbering and simplify journal dispatch.
- Unify adopted workflow pointers with the standard Skill and refresh the non-checkbox identity.

- Use the standard `signetum` Skill for reviewed new/existing-project adoption;
  retain application tools and use a local portable runtime for daily work.
- Use `.agents/signetum` consistently without a `repo-dev` runtime alias.
- Keep one approved change record, significant append history and a derived
  decision set. Retire the old active workflow and preserve original rationale.
- Use manifest schema 3 with one `repository.changes` root and independent
  schema/product versions; remove ineffective retry settings and old bindings.
- Contain worktrees under the primary repository, retire removed registrations
  and safely clean up after delivery without deleting the active executor.
- Share supervised diagnostics and gate verdicts, preserving first failures,
  owned-process settlement and complete final validation. Optional selection,
  weighted scheduling and CI partitions remain source-bound optimizations.
- Maintain the engine once and derive portable runtime artifacts. Consolidate
  user guides, remove obsolete files and disclose test changes and evidence loss.
- Replace the mascot variants with compact branding and a bilingual, accessible
  static homepage with a direct Skill installation action.
- Prepare one package/Skill release with wheel/sdist, component metadata and
  checksums; hosted coverage requires all platforms and PyPI stays opt-in.

## 0.1.0 - 2026-08-30

- Start the public Template version line without rewriting the historical v2
  and v3 architecture tags.
- Use self-contained TOML Review and Specification contracts.
- Enforce Review-to-Specification-to-Plan ownership in member and final gates.
- Align the copied repository's delivery branch with GitHub's `main` default.

## 3.0.0 - 2026-08-30

- Separate the RepoSeal engine branch from the rendered default-branch Template.
- Rename the distribution, import package, manifest identity, CLI, receipts,
  and profile authority to `reposeal` without compatibility aliases.
- Add a deterministic, minimal Template with equivalent English and Simplified
  Chinese entry points and no engine, editor, or maintainer residue.
- Package the eight lifecycle operations so cloned repositories pin one exact
  released RepoSeal version instead of vendoring engine code.

## 2.0.0 - 2026-08-30

- Launch RepoSeal as an Agent-native, standalone GitHub Template.
- Establish “Seal every change with evidence” as the public product position
  with one canonical seal-and-repository visual identity.
- Document the complete Review-to-acceptance lifecycle, Agent Team batch
  delivery, behavior-oriented testing, and customization boundaries.
- Introduced typed repository manifests, profiles, and the check-only CLI.
- Added Review, Specification, Plan, evidence, delivery, acceptance, and reopening traceability.
- Added isolated workspaces, named batch assembly, frozen final validation, and explicit delivery.
