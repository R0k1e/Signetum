# Application policy

Before implementation, search all production and test paths named by the
architecture. Reuse one authority. Add targeted behavioral validation while
working, and run repository-owned complete validation only on the frozen batch.

Before adding evidence, classify affected tests as retain, extend, merge,
replace, delete or new. Keep the necessary real public traversal and put pure
matrices in core tests. Do not pin teaching prose or private call order. Reuse
successful immutable preparation, with separate mutable state per test.

Use the repository's declared test command through
`just -- protocol test --shard <declared-shard> -- <native-arguments>` for explicit
feedback after preparation. This diagnostic preserves the existing argv and
uses the normal allocator and supervisor without granting readiness. Do not
multiply inner workers or start redundant full suites concurrently. Use actual
phase cost before changing widths or fixture scope; keep measurements in logs,
without permanent count/timing gates or another inventory.
