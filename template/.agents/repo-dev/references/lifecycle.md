# Lifecycle policy

Use one approved change record and an append-only significant source journal.
Read the current decision working set before work; retrieve history as needed.
Use repository-owned authoring, journal and validation tools. Preserve accepted
legacy files until explicit migration. Work in a registered member workspace
and stop at ready unless integration or delivery is authorized. Final generates
the review from frozen evidence; do not maintain another handwritten report.

When behavior, responsibility, commands or prerequisites change, update affected
current architecture and usage guidance in that same change. Check those sources
before ready; link validity alone does not prove they are current. Keep reasons
in the existing history and do not create a separate maintenance report.

Accepted decision transactions live in the owning change by default. Use a
standalone ADR only when it needs an independent cross-change authority, and
reference that basis instead of repeating it. Routine choices create no new file.
