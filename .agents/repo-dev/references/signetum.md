# Foundation policy

Generic mechanisms stay in `signetum`; repository facts stay in
the specialization manifest, change packages, architecture, and adapters.
Validation is check-only. Publishing and delivery require explicit authority.
Unsupported schema and profile identities fail without fallback interpretation.

Present the approved behavior and acceptance evidence before implementation.
Record significant discoveries through `just protocol` for consolidated changes;
legacy packages retain their declared deviation API. Do not keep findings only
in chat or edit JSON Lines state directly. A refused request has not entered
history: commit changed authority bindings before retrying, and verify the
returned applied transaction rather than continuing on an assumed write. Safe
implementation clarification may continue, but freeze an affected unauthorized
decision while independent work proceeds. Before final validation, reconcile
every retained deviation into the applicable durable authority or an explicit
terminal disposition. After final, present the generated commitment-to-delivery
review before requesting explicit delivery.

Classify existing affected tests as retain, extend, merge, replace, delete or new
before adding evidence. Extend an existing public traversal where possible;
add a new traversal only for a distinct public boundary. Core tests own pure
matrices. Generated and installed runtimes keep representative independent
execution, including their adapter-specific failures. Do not pin teaching prose,
private call order or historical filenames. Static checks own declared static
constraints; ordinary documentation edits do not require new tests.

Develop Signetum through the shipped protocol and implementation owners. Exercise
the actual CLI and installed Skill where usability is affected. Treat self-use
friction and verified Perdura lessons as inputs to generic product repairs;
keep application-specific policy outside the core. Include protocol maintenance,
installation and review burden when judging an improvement.
